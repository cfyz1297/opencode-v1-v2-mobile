# OpenCode V1/V2 Mobile (форк cfyz1297)

**Русский** | [English](README.md) · [llms.txt](llms.txt)

> **Android-клиент для AI-агента OpenCode.** Управляйте сессиями `opencode serve` с телефона: живой транскрипт, подтверждение инструментов, диффы, смена модели и уровня рассуждений — по локальной сети, Tailscale или через туннель. Работает с **opencode 1.x (V1 API) и 2.x (V2 API)**, версия определяется автоматически.

Форк [dzianisv/opencode-mobile](https://github.com/dzianisv/opencode-mobile), собран на Expo/React Native. Распространяется только как APK из GitHub Releases — без магазинов, без аккаунта и без собственного бэкенда: приложение общается напрямую с вашим сервером.

Репозиторий раньше назывался `opencode-mobile`, в 0.3.0 переименован в `opencode-v1-v2-mobile`. Старые ссылки перенаправляются, а имя файла APK (`opencode-mobile-v2.apk`) оставлено прежним: на него опираются встроенная проверка обновлений и цепочка проверки подписи релиза.

Версия **0.3.21 (86)**. Обновляется поверх 0.3.20 без удаления приложения.

> **Статус:** каждая сборка прогоняет 833 автотеста и Android CUA smoke на эмуляторе. Против настоящего сервера opencode 1.18.x ещё не проверялось; планшетный интерфейс, мастер туннелей и офлайн-история проверены в коде и на эмуляторе.

Смежные проекты: [dzianisv/opencode-mobile](https://github.com/dzianisv/opencode-mobile) (оригинал, только V1), [sst/opencode](https://github.com/sst/opencode) (сам агент), `opencode serve` в Termux на Android.

**Поисковые запросы, по которым сюда попадают:** opencode на андроид · opencode android client · opencode v2 api android · opencode 1.x клиент · управление AI-агентом с телефона · opencode serve tailscale · opencode mobile.

## Установка (Android, APK)

Стабильная ссылка — всегда последний релиз:

- **[Скачать opencode-mobile-v2.apk](https://github.com/cfyz1297/opencode-v1-v2-mobile/releases/latest/download/opencode-mobile-v2.apk)** (~86 МБ)
- Все релизы: [Releases](https://github.com/cfyz1297/opencode-v1-v2-mobile/releases) — на каждый новый билд свой релиз (`0.2.15`, `0.2.18`, `0.3.0`, …). Файл APK по-прежнему называется `opencode-mobile-v2.apk`: на это имя опираются проверка подписи в CI и ссылка встроенной проверки обновлений, поэтому оно намеренно не менялось.

> ⚠️ Разовая переустановка: начиная с `0.2.9` APK подписывается постоянным ключом (раньше на каждый билд генерировался новый debug-ключ, поэтому обновление поверх не устанавливалось). Если стоит сборка старее — удалить её **один** раз и поставить текущую, дальше обновления ставятся поверх без удаления.

APK собирается GitHub Actions из `main` этого репозитория и подписывается постоянным ключом из секретов репозитория (без секрета — debug-ключ). Google Play / F-Droid / App Store — не используются: эти workflow отключены. Активны только `Build Android APK` и `Security scan`.

## Подключение к серверу opencode

Приложение говорит на **обоих поколениях API**: opencode 1.x (V1, его до сих пор ставит `npm install -g opencode-ai`) и opencode 2.0.x+ (V2, ставится нативным бинарником). При подключении адрес один раз опрашивается, ответ запоминается для этого подключения, и дальше используется подходящий транспорт — `/global/health` + `/global/event` для V1, `/api/info` + `/api/event` для V2. Определение идёт по телу и типу ответа, а не по коду: неизвестный маршрут на обоих поколениях проваливается в веб-интерфейс и отвечает `200 text/html` — именно поэтому клиент, знавший только V2, показывал «подключено» на V1-сервере и падал на первом же настоящем запросе.

Если автоопределение ошиблось, **Настройки → Сервер → API сервера** принудительно включает `v1` или `v2` для активного подключения.

Для V2:

1. Поставить и запустить сервер:

   ```bash
   curl -fsSL https://opencode.ai/v2/install | bash
   OPENCODE_SERVER_PASSWORD=вашпароль opencode serve --hostname 0.0.0.0 --port 4096
   ```
2. В приложении: **Add Connection** → адрес сервера (`http://IP:4096`), логин `opencode`, пароль из команды выше.

**На Android** сервер ставится из [opencode-termux](https://github.com/cfyz1297/opencode-termux): это OpenCode 2, собранный под Bionic, поэтому он работает прямо в Termux — без glibc, proot и слоёв совместимости.

```bash
curl -fsSL https://raw.githubusercontent.com/cfyz1297/opencode-termux/main/install.sh | bash
OPENCODE_SERVER_PASSWORD=вашпароль opencode serve --hostname 0.0.0.0 --port 4096
```

Обновление — `opencode upgrade` или повторный запуск команды установки. Сборки начиная с `2.2.5-r1` содержат исправление падения TUI на Android 17 (`Pointer exceeds safe integer range`); API сервера тот же, что у официального бинарника V2.

Формат V2 (проверено на 2.0.27): Basic-аутентификация только в виде `opencode:<пароль>` (Bearer и пустой пользователь = 401), все пути `/api/*`, страничные ответы `{data, cursor}`, SSE `GET /api/event`.

## Что умеет приложение

**Сессии и чат**
- Живой транскрипт: текст, рассуждения, вызовы инструментов, диффы и сводки компакции — в том порядке, в котором их выдала модель.
- Уточнение можно отправить, пока агент ещё работает: сервер ставит промпт в очередь.
- Кнопка «стоп» следует реальному статусу прогона на сервере, поэтому прервать можно и запуск, начатый не с этого экрана (приложение перезапускалось, другая сессия, открыли посреди работы).
- Редактирование сообщения с откатом сессии к нему (`revert` / `unrevert`), компакция истории в сводку.
- Запросы подтверждения инструментов и вопросы агента появляются прямо в диалоге; отвеченные вопросы остаются в переписке свёрнутой строкой, а неотвеченный вопрос рисуется под сообщением, которое его задало.
- **Сабагенты видны, пока работают.** Делегированный агент живёт в отдельной дочерней сессии: карточка запустившего его инструмента показывает строку с задачей, агентом, живым статусом и тапом в транскрипт ребёнка — в том же рабочем пространстве, что и родитель. Два счётчика под шапкой показывают текущую партию и сколько сабагентов сессия делегировала всего; работающие идут первыми. Дочерние сессии не попадают в список «Недавние».
- Текст раскладывается по собственным метрикам шрифта, поэтому последняя строка абзаца не срезается на телефонах с темой системного шрифта.
- Неудачный прогон показывает причину от сервера вместо пустого пузыря.
- **Работа модели свёрнута в одну строку на ответ.** Всё, что модель сделала между двумя ответами — рассуждения и все вызовы инструментов — собирается в одну строку, которая называет, что запускалось, и сколько это заняло (`5 · Оболочка, Чтение · 12.3s`), со спиннером во время работы и крестиком при ошибке. Раскрытие показывает те же блоки рассуждений и карточки инструментов, что были раньше. Делегирование сабагента не сворачивается никогда: это единственный вход в дочернюю сессию.
- **Навигатор по длинным сессиям.** Компактная панель над композером считает ваши сообщения (`3 / 12`), листает на одно вверх и вниз и уводит в конец двойной стрелкой. Появляется при прокрутке и прячется через мгновение, поэтому не лежит на тексте; один тап — ровно одно сообщение, и переход мгновенный.
- Неудачная загрузка, отправка или прерывание теперь видны: баннер с текстом ошибки, что делать дальше, «Копировать» и «Скрыть». Баннер переподключения добавляет причину последнего обрыва.
- Размер страницы считается в промптах (5 / 10 / 25 / 50 / **Вся**). «Вся» загружает весь транскрипт. Обновление при возврате в приложение сохраняет уже показанную историю, а не заменяет её последней страницей сервера.

**Информация о сессии**
- Кнопка в заголовке — кольцо, заполняемое по расходу контекста (синее, жёлтое после 50 %, красное после 80 %).
- В панели: токены, процент контекста с полоской, общая стоимость за всю сессию, модель и агент сессии.

**Модели и агенты**
- Пикер моделей с поиском, группировкой по провайдерам и отметкой активной модели.
- **Любимые модели**: звёздочка в любом пикере закрепляет модель в секции «Любимые» сверху; хранится только на устройстве и общее для всех подключений.
- Скрытые модели (экран «Модели») исчезают из обоих пикеров.
- Выбор уровня рассуждений (variant) для моделей, которые его поддерживают; шторки поднимаются вместе с клавиатурой, ни одна строка не остаётся под ней.

**Подключения и серверы**
- Несколько подключений: локальная сеть, Tailscale, туннель; пароли в Keystore/Keychain.
- **Поддержка V1 и V2** с автоопределением и ручным переключателем.
- Честный статус: «активно» значит, что сервер ответил; проверка при открытии вкладки, раз в 15 с и при возврате в приложение.
- Мастер туннелей для Cloudflare (именованные туннели) и ngrok.
- Экран провайдеров: подключение по API-ключу через сервер; в APK ключи не хранятся.
- Экран диагностики с копируемым отчётом (разбор URL, оба health-маршрута, определённое поколение API, доступность интернета).

**Надёжность и приватность**
- Восстановление после сбоев: watchdog потока, перечитывание переписки после тишины, `GET /api/session/active` для снятия «работает».
- Офлайн-история: шифрованная, только для чтения, с ограничениями.
- Телеметрии нет: Sentry и PostHog удалены.
- Биометрическая разблокировка, уведомления с фиксированным текстом (без присланных сервером имён инструментов и путей на экране блокировки).
- Планшетный интерфейс, любая ориентация, нативная подстройка под клавиатуру.

## Чем форк отличается от оригинала

Основа — [dzianisv/opencode-mobile](https://github.com/dzianisv/opencode-mobile) на теге `v0.4.15` (14.08.2026). Транспорт 1.x из `v0.4.16` и фикс заголовка сессии из `v0.4.17` перенесены вручную. В оригинале с тех пор вышли `v0.4.16` … `v0.4.23`; эти релизы прочитаны по коммитам, и взято только то, что подходит одному пользователю с одним сервером. От `v0.4.15` у форка своя линия версий, сейчас **0.3.21**.

Расчётная схема — `opencode serve` **в Termux на том же телефоне**, через `127.0.0.1`: поэтому приложение разрешает cleartext до loopback и держит foreground-сервис для уведомлений. Удалённый сервер в локальной сети, туннель Cloudflare или Tailscale тоже работают; приложение нигде не предполагает собственный бэкенд.

| Что | Оригинал (`v0.4.23`) | Форк (0.3.21) |
|---|---|---|
| API сервера | только 1.x (`/session`, `/global/*`) | **оба**: 1.x и 2.x (`/api/*`), автоопределение, принудительный выбор в настройках |
| Задача | много пользователей, доставка через магазины | один пользователь, один сервер, один канал: APK |
| Доставка | Google Play, свой F-Droid, APK, EAS, конфиг iOS на месте | только APK из GitHub Releases; `eas.json`, store-workflow, fastlane и цель iOS удалены |
| Телеметрия | Sentry + PostHog | обе зависимости и плагин Sentry удалены |
| Языки | en / ru / zh-Hans, по 322 ключа | те же три, по 461 ключу, плюс тест паритета, который роняет сборку при расхождении |
| Ориентация | только портрет | любая; планшетная раскладка от 768 dp, две панели от 1000 dp |
| Офлайн-история | нет | зашифрованная копия только для чтения (Keystore / Keychain) |
| Туннели | только форма подключения | мастер Cloudflare (именованные туннели) и ngrok |
| Экран моделей | нет | поиск, группы, видимость — питает оба пикера |
| Статус подключения | «выбрано» считается активным | реальный ответ сервера, опрос при фокусе и каждые 15 с |
| Восстановление прогона | нет | сторож тишины, перечитывание транскрипта, `GET /api/session/active` |
| Выбор модели | поиск + группы | + избранное (закреплённая секция сверху) |
| Информация о сессии | счётчик токенов | кольцо контекста в шапке, полоса контекста, расход по всей сессии |
| Список сессий | последняя страница | проходит курсор сервера, до 800 корневых сессий |
| Строки инструментов | имя + сырой payload | команда для `shell`, живой заголовок прогресса, fallback на вход, без пустого раскрытия |
| Сабагенты | секция «Subagents» над транскриптом: счётчики и строки, только чтение | строка внутри карточки запустившего инструмента, всегда видна, тап открывает дочернюю сессию в рабочем пространстве родителя; два счётчика под шапкой (текущая партия / всего за сессию); дети не попадают в «Недавние» |
| Строки работы | рассуждения и вызовы инструментов идут как пришли | один спойлер на ответ с именами инструментов и общим временем; делегирование остаётся снаружи |
| Длинные сессии | плавающие кнопки поверх текста | панель-навигатор над композером, видна при прокрутке и скрыта в покое, листает ваши сообщения |
| Ошибки сессии | ошибка стора пишется, но не показывается | баннер с текстом, следующим шагом, «Копировать» и «Скрыть» |
| Текст сообщений | явный `lineHeight` | без `lineHeight`: Android считает коробку строки по метрикам шрифта — явный обрезал последнюю строку (см. 0.3.20) |
| Клавиатура | inset из JS | нативный IME inset из `MainActivity` |
| Папка новой сессии | по умолчанию | выбранный проект (`location.directory` в теле запроса) |
| Фон | уведомления, пока приложение запущено | headless keep-alive сервис, опрос сервера, иконки по категориям, foreground-тип `specialUse` |
| Тесты | `node --test` по glob | `scripts/run-tests.mjs` + порог покрытия 80 % + CUA smoke на эмуляторе Android 15 |

Что изменено в коде:

- **Адаптер `src/lib/v2-compat.ts`**: ответы и события V2 нормализуются в форму V1, поэтому сторы и экраны остались как были. События V1 (`session.status`, `message.part.updated`) собираются из дельт V2 (`session.text.delta`, `session.reasoning.delta`, `session.tool.*`). `state.metadata` инструмента пробрасывается — именно это позволяет карточке `subagent` ссылаться на дочернюю сессию.
- **SDK** работает через `/api/session`, `/api/event`, `/api/info`, `/api/permission/request`, `/api/fs/*`, `/api/project`, `/api/location`. Смена модели или агента сессии идёт через `POST /api/session/{id}/model` и `/agent`. Дети запрашиваются как `GET /api/session?parentID=…`, фильтр на стороне сервера.
- **Транспорт V1** (`src/lib/sdk-v1.ts`, `src/lib/api-detect.ts`): то же приложение работает с сервером opencode 1.x — `/session`, `/experimental/session`, `/session/{id}/prompt_async`, `/global/event`. Определённый API хранится в подключении (`api`, `serverVersion`) и сбрасывается при смене URL. Взято из upstream PR #209 / `v0.4.16`.
- **Сабагенты** (`src/lib/subagent-status.ts`, `src/components/chat/SubagentRow.tsx`, `SubagentBar.tsx`): делегирование видно, пока работает, и открывается как обычная сессия. Статус берётся из живого состояния прогона, штампов `busy`/`idle` ребёнка или карты ошибок по сессии — последние два нужны, потому что ребёнок мог завершиться или упасть до подключения клиента.
- **Карточки инструментов** (`src/lib/tool-view.ts`): инструмент `shell` (имя в 2.x) рисуется как терминал с командой, показывается заголовок прогресса из `session.tool.progress`, пустой вывод заменяется входом, и нажимается только заголовок — чтобы дифф внутри карточки можно было тащить вбок.
- **Статистика сессии** (`src/lib/session-stats.ts`, `src/components/chat/ContextRing.tsx`): одна функция считает токены, процент контекста и расход, её используют и кольцо в шапке, и панель информации, поэтому они не могут разойтись.
- **Новые экраны и логика**: `app/history.tsx` (офлайн-история), `app/models.tsx` (видимость моделей), `app/providers/*` (каталог провайдеров и подключение по ключу через сервер), `app/connection/tunnel.tsx` (мастер туннелей), `src/components/TabletSessions.tsx` (планшет), `src/lib/adaptive-layout.ts`, `src/lib/connection-health.ts`, `src/lib/connection-security.ts`, `src/lib/run-watchdog.ts`, `src/lib/stream-watchdog.ts`, `src/lib/keyboard-inset.ts`, `src/lib/message-page.ts` (страницы в промптах, `ALL_TURNS`, `keepLoadedHistory`), `src/lib/session-stats.ts`, `src/lib/tool-view.ts`, `src/lib/api-detect.ts`, `src/lib/subagent-status.ts`, `src/stores/model-favorites.ts`.
- **Специфика V2**: вопросы агента идут через формы V2 и рисуются под сообщением, которое их задало; сводки компакции видны в транскрипте; вложения-изображения показываются как изображения; лента следует за потоком; композер очищается после встроенной команды.
- **Изоляция клиента**: клиент SDK привязан к своему подключению, поэтому потоковые сообщения и выбранная модель не утекают между серверами.
- **Удалено вместе с инфраструктурой**: `website/`, `docs-site/`, `fastlane/`, `fdroid/`, `distribution/`, `eas.json`, `.maestro/`, `.autopilot/`, `.supervisor/`, `.tasks/`, сборка под iOS и workflow публикации в магазины, плагин Sentry и загрузка source-map.
- **Безопасность**: разрешение `SYSTEM_ALERT_WINDOW` заблокировано, пароли и офлайн-копии пишутся с политикой `WHEN_UNLOCKED_THIS_DEVICE_ONLY`, форма подключения предупреждает о пароле по незашифрованному `http://`. Уведомления о подтверждениях и вопросах несут фиксированный текст, а не имена инструментов, пути или тексты вопросов с сервера, потому что шторка читается с заблокированного телефона (аудит upstream M-03, перенесён). Запросы несут `ngrok-skip-browser-warning` / `Bypass-Tunnel-Reminder`, чтобы туннель проксировал API, а не отвечал своей заглушкой.

Чего у форка нет: OAuth-подключений провайдеров (только API-ключ), OpenCode Cloud, сборки под iOS, публикации в магазины, телеметрии.

Подробнее — [upstream README](https://github.com/dzianisv/opencode-mobile#readme).

## Безопасность

- Пароли серверов и офлайн-история лежат в Android Keystore / iOS Keychain с политикой `WHEN_UNLOCKED_THIS_DEVICE_ONLY`: они не попадают в резервные копии ОС и не восстанавливаются на другом устройстве.
- Обычный `http://` не шифрует ни пароль, ни переписку. Формы подключения предупреждают об этом; для недоверенных сетей используйте https, туннель или Tailscale. Loopback (Termux на том же телефоне) предупреждения не показывает — трафик не покидает устройство.
- Приложение не запрашивает `SYSTEM_ALERT_WINDOW` (рисование поверх других приложений).
- Зависимости сборки: `npm audit` показывает 34 записи (7 high) в цепочке Metro/PostCSS/Expo CLI. `npm audit fix --force` откатывает Expo до 51 и ломает проект. В поставляемый APK этот код не входит — он исполняется только при сборке на CI.

## Мастер Cloudflare / ngrok

Для Cloudflare нужен **именованный туннель**, аккаунт и домен: в панели Cloudflare создайте Tunnel и Published application route с Service URL `http://127.0.0.1:4096`, затем запустите команду с токеном на компьютере. Токен Cloudflare в приложение не вводится. Быстрые адреса `trycloudflare.com` отклоняются мастером: [они не поддерживают SSE](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/#limitations), необходимый для потоковых ответов. Альтернатива без своего домена — ngrok. Установку cloudflared/ngrok и вход в ngrok выполняет владелец компьютера.

### 0.3.21

- **Возврат в приложение больше не теряет историю.** Обновление при возврате из фона и пересинхронизация после реконнекта запрашивали у сервера страницу по умолчанию — 50 сообщений — и заменяли ею всё на экране. Старые обмены вместе с карточками сабагентов исчезали до переоткрытия сессии, а длинный транскрипт выглядел обрезанным. Теперь запрос идёт по настройке страницы (или за всю сессию), уже загруженная история сохраняется, а поздний ответ не может попасть в сессию, на которую вы только что переключились. Дочерние сессии перечитываются при возврате, поэтому сабагент, завершившийся в фоне, перестаёт показывать «Idle».
- **Работа модели — одна строка на ответ.** Каждый блок рассуждений и каждая карточка инструмента выводились подряд, и долгий прогон выталкивал ответ с экрана. Теперь всё между двумя ответами сворачивается в одну строку — `5 · Оболочка, Чтение · 12.3s` — которая считает шаги всего отрезка, а не пишет «шаг 1» на сообщение, берёт имена из каталога, суммирует время (тикает, пока что-то выполняется) и превращается в крестик при ошибке. Раскрытие показывает прежнее оформление без изменений. Подряд идущие шаги ассистента стали одной строкой ленты, поэтому шапка, «Скопировать» и токены появляются один раз. Делегирование сабагента намеренно остаётся снаружи: сворачивание спрятало бы единственный вход в дочернюю сессию.
- **Навигатор по длинным сессиям.** Плавающая кнопка «в конец» могла закрыть строку текста. Теперь это компактная панель над композером — счётчик, на одно сообщение вверх, на одно вниз, двойная стрелка в конец, — которая появляется при прокрутке и гаснет через 3.5 с после остановки. Листает **ваши собственные сообщения**: вопрос не стримится, не склеивается и не меняет высоту, в отличие от ответа; позиция берётся из разложенных строк, поэтому она верна сразу при открытии сессии и первый тап работает без предварительного свайпа. Переходы мгновенные, а не анимированные: анимация на длинном транскрипте читалась как зависание.
- **Ошибки видны.** `useSessions.error` писался в пятнадцати местах и не показывался нигде: неудачная загрузка или отправка выглядели как пустая замершая сессия. Теперь баннер показывает текст сервера, что делать дальше, и «Копировать» / «Скрыть». Баннер переподключения добавляет причину последнего обрыва, её тоже можно скопировать.
- **Markdown-картинки больше не роняют экран.** `react-native-marked` 8.0.0 запрашивает размер картинки в эффекте без массива зависимостей, а его колбэки ставят свежий стейт, поэтому любой `![](url)` перерисовывался до срабатывания защиты React от глубины обновлений. Теперь картинки рисует свой компонент с запросом по URI (SVG остаётся у библиотеки — там эффект ограничен). Ключи React больше не берутся из `github-slugger`, который хранил свойство на каждый вызов в долгоживущем рендерере и мог упереться в лимит Hermes в 196 607 свойств внутри одного огромного сообщения.
- **Длительность инструментов переживает переоткрытие.** Сервер присылает собственные часы tool-части (`created`, `ran`, `completed`); маппер истории их выбрасывал, поэтому в переоткрытой сессии не было длительностей и свёрнутая строка не могла показать общее время. Оба транспорта теперь используют общее рукопожатие SSE с лимитом: поток V1 раньше подключался без срока и мог висеть вечно, уже отчитавшись «подключено».

### 0.3.20

- **Последняя строка сообщения больше не обрезается.** RN реализует `lineHeight` спанами, а `CustomLineHeightSpan` приравнивает низ последней строки блока к заявленному descent шрифта. У шрифта, чьи глифы выходят ниже (тема системного шрифта на телефоне, в отличие от Roboto эмулятора), низ последней строки каждого абзаца срезался, а внутренние строки только перекрывались и выглядели нормально. Поэтому дефект всегда попадал на последнюю строку, выглядел одинаково на всех сборках и не воспроизводился на эмуляторе ни при какой плотности. `lineHeight` больше не задаётся, и Android считает коробку строки по реальным метрикам шрифта.
- **Код в раскрытой карточке инструмента листается вбок.** Вся карточка была одним `TouchableOpacity`: тап или свайп по диффу всплывал в неё и сворачивал карточку — код не «отказывался листаться», а исчезал под пальцем. Теперь нажимается только заголовок, а горизонтальный `ScrollView` получает `nestedScrollEnabled`: транскрипт — вертикальный `FlatList`, и Android отдаёт вложенному скроллеру жест только при идеально горизонтальном движении.
- **Сабагенты видны и открываются.** Делегирование не оставляло следа: инструмент возвращается в момент запуска, поэтому родитель выглядел простаивающим, пока ребёнок работал. Теперь карточка запустившего инструмента рисует строку с задачей, агентом, живым статусом (Running / Done / Failed / Idle) и тапом в транскрипт ребёнка — в рабочем пространстве родителя. Два счётчика под шапкой показывают текущую партию и общее число за сессию, работающие идут первыми. Дочерние сессии не попадают в «Недавние», а их статус берётся из живого состояния прогона или `idle`-штампа, поэтому сабагент, завершившийся до подключения приложения, всё равно читается как Done.
- **Карточка вопроса рисуется там, где вопрос задан** — под сообщением, чья форма его задала, и транскрипт прыгает к ней, — а не над композером вне ленты, где её не видел никто, прокрутившийся выше, и прогон выглядел зависшим.
- **Тёмный экран после долгого фона больше не появляется.** `HeadlessJsTaskService` возвращает `START_REDELIVER_INTENT`, поэтому после смерти процесса Android перезапускал keep-alive сервис и поднимал *headless* React-инстанс; следующее открытие прикрепляло Activity к хосту, запущенному без Activity, сплэш не скрывался, и приложение закрывалось. Теперь возвращается `START_NOT_STICKY`. Отдельно: Android 15 ограничивает foreground-сервис `dataSync` шестью часами за 24 и убивает приложение по исчерпании бюджета — сервис использует `specialUse` на API 34+ и останавливается сам по таймауту.
- **Мелочи из апстрима:** падающий запуск камеры больше не оставляет кнопку мёртвой, `aborted` от распознавания речи не показывается как ошибка, а поток событий сдаётся через 15 с, если сервер не отдал заголовки, вместо «Connected» над мёртвым сокетом.

### 0.3.17

- **Уведомления в фоне.** React Native останавливает свои JS-таймеры, когда приложение уходит в фон, поэтому уведомления не рождались. `KeepAliveService` держит headless-задачу весь прогон, а сторож опрашивает сервер вместо локального состояния: завершение, вопросы и запросы разрешений доходят до заблокированного телефона.
- **Иконки уведомлений** по категориям (вопрос, ошибка, завершение, разрешение) из небольшого нативного модуля: Android рисует small icon как монохромную маску, а expo-notifications подставляет белый квадрат.
- **Отвеченные вопросы остаются под сообщением**, которое его задало; карточка «Сессия выполняется» убрана; выбор модели закрывает клавиатуру; уведомления приходят только когда приложение свёрнуто, одно на прогон, с дедупликацией.

### 0.3.7

- **Голосовой ввод впервые работает.** В `expo-image-picker` стоял `microphonePermission: false`, а этот плагин трактует `false` как *блокировку* разрешения: expo писал `<uses-permission android:name="android.permission.RECORD_AUDIO" tools:node="remove"/>`. В итоговый манифест `RECORD_AUDIO` не попадал вовсе, поэтому запрос разрешения мог ответить только «denied». Проверено `aapt dump permissions` на предыдущем релизе: разрешения нет. Опция появилась тем же коммитом, что и голосовой ввод, — фича не работала никогда. Теперь CI валит сборку, если в релизном APK нет этого разрешения.

- **Вложение фото больше не падает молча на самом нажатии.** Тап по «+» закрывал клавиатуру и сразу показывал «изображение не прикреплено», не открывая пикер: системная activity выбора фото отклоняла запуск до любого выбора. Теперь приложение повторяет попытку со старым интентом `ACTION_GET_CONTENT`, который на устройстве всегда обслуживает файловый менеджер.

### 0.3.5

- **Долго работающий инструмент больше не выглядит как зависшее приложение.** Длительность в строке показывалась только когда есть и начало, и конец, а у выполняющегося инструмента конца нет — поэтому десятиминутная команда висела без признаков жизни. Теперь прошедшее время тикает каждую секунду и после первой минуты показывается как `5m 05s`. Вдобавок V2-сервер вообще не присылает время для инструментов (проверено на живом сервере: `{status, input, content, metadata}` и больше ничего), поэтому адаптер V2 теперь строит это окно из отметок событий, а не рассчитывает на готовое.

### 0.3.4

- **Текст в чате рисуется чисто.** Inline-код подсвечивался плашкой. На Android плашка позиционируется по собственному боксу фрагмента кода, поэтому у переносящегося фрагмента она выше своей строки и закрывает буквы над собой, а уменьшенный шрифт кода сдвигает плашку примерно на полстроки вниз. Воспроизведено на эмуляторе Android 15 в нескольких вариантах стиля: глифы везде стоят правильно, съезжают только прямоугольники — значит, дефект в самой подсветке. Теперь inline-код выделяется только цветом и моноширинным шрифтом.
- **Списки моделей и усилия больше не пустые.** Каталог провайдеров загружался один раз на соединение; если этот запрос попадал на заблокированный телефон или недоступный сервер, оба окна оставались пустыми до перезагрузки через Настройки → Модели. Теперь неудачный запрос сохраняет уже загруженный список (в пределах соединения, чтобы модели другого сервера не подмешивались), возврат в приложение обновляет каталог, а открытие списка с пустым каталогом сначала запрашивает его заново.

### 0.3.3

- **Оповещение об обновлении снова работает.** Открытие страницы релиза теперь действительно помечает версию просмотренной и убирает полосу: `Linking.openURL` резолвится в `void`, поэтому прежняя проверка результата никогда не срабатывала. Плашка также перепроверяет обновления при возврате приложения на передний план, а строка «О приложении» обновляется при каждом открытии настроек, а не только при первом монтировании.
- **Ответ, полученный в фоне, больше не печатается заново.** При возврате приложение заменяет поток SSE до обновления транскрипта, поэтому накопившийся за время фона бэклог отбрасывается, а не перерисовывает готовый ответ более старыми и короткими снимками. Кроме того, текстовые части и рассуждения только растут во время прогона — устаревшая дельта не может их сократить.
- **Долгое сворачивание больше не вешает сессию.** Android может убить сокет событий без ошибки, пока JS приостановлен, а сторож зависаний следил только за активными прогонами — после возврата приложение могло молчать, пока следующий промпт не отстоит 30 секунд. Возврат после 15+ секунд в фоне теперь открывает новый поток и пересинхронизирует открытую сессию, статус занятости и висящие формы подтверждений/вопросов. Быстрое переключение приложений поток не трогает.

### 0.3.2

- **Редактирование подключения сохраняет верный API.** «Проверить подключение» теперь переживает «Сохранить», а сохранение того же адреса заново опрашивает сервер — замена V1 на V2 по тому же URL больше не оставляет старую версию протокола. Ответ `401/403` на `/api/info` больше не считается доказательством V2: V1 за паролем отвечает так же.
- **Голосовой ввод использует локаль телефона.** `ru-RU` и `zh-CN` уходят в распознаватель как есть, без подмены на `ru-US` / `zh-US`.
- **Локализация чата и уведомлений.** Подписи ролей и заголовки/тексты системных уведомлений берутся из en / ru / zh-Hans; серверный текст в шторку по-прежнему не попадает.
- **Тесты проверяются типами.** `*.test.ts(x)` возвращены в `tsconfig.json`, 49 ошибок типов в тестах исправлены.
- **Легче CI и сборка.** `versionCode` / `versionName` читаются из `app.json`, сертификат подписи сверяется с закреплённым SHA-256 без скачивания предыдущего APK на 86 МБ, а собранный APK проверяется на `SYSTEM_ALERT_WINDOW` и `debuggable`.
- **Исправления безопасности.** Диагностика больше не логирует и не отдаёт креды, вшитые в URL; id сессии из deep link или уведомления проверяется перед подстановкой в путь API. Полный отчёт — `docs/security-review-0.3.2.md`.
- **Меньше запросов и записей.** Смена модели и агента идёт параллельно; переключение активного подключения пишет SecureStore один раз.
- **Удалено:** `@tanstack/react-query`, форма и очередь waitlist `agentlabs.cc`, мёртвый клиент Chatwoot, `android/sentry.properties`, dev-флаг сетевого инспектора в релизе. Общие HTTP-слой, разбор сохранённого JSON и части пикеров моделей заменили дубли.

### 0.3.1

- **Нет краша при выходе из сессии во время стрима.** Заголовок экрана сессии заново регистрировал нативные опции на каждой порции потока, поэтому выход из экрана, пока прогон печатал ответ, мог разобрать экран посреди этого обновления (`react-native-screens`, «child already has a parent»). Теперь опции применяются через `navigation.setOptions` в эффекте, который срабатывает только при изменении видимых данных заголовка — названия, бейджа папки, процента кольца, темы. Порт из апстрима v0.4.17.

### 0.3.0

- **Работает с opencode 1.x и 2.x.** Второй транспорт (`src/lib/sdk-v1.ts`) закрывает V1 API — `/session`, `/experimental/session`, `/session/{id}/prompt_async`, `/global/event`, права, вопросы, файлы, агенты, команды, провайдеры. Адрес один раз опрашивается на подключение, ответ запоминается; определение идёт по телу и типу ответа, а не по коду, потому что неизвестный маршрут на обоих поколениях проваливается в веб-интерфейс и отвечает `200 text/html`. **Настройки → Сервер → API сервера** принудительно включает `v1` или `v2` (сразу, без перезапуска). События, которые присылает только 1.18.x (`session.idle`, `permission.updated`, `permission.v2.*`), нормализуются — иначе запрос подтверждения не появился бы, а прогон висел бы вечно.
- **Любимые модели.** Звёздочка в строке закрепляет модель в секции «Любимые» сверху обоих пикеров. Хранится на устройстве (только id провайдера и модели), общее для всех подключений; любимая модель остаётся и в списке провайдера, скрытая — остаётся скрытой.
- **Карточки инструментов больше не пустые.** Три причины: заголовок прогресса из `session.tool.progress` принимался и выбрасывался, пустая строка вывода скрывала входные данные, а имя `shell` в 2.x не распознавалось (был только `bash`) — не было ни иконки терминала, ни команды. Решение вынесено в `src/lib/tool-view.ts` и покрыто тестами.
- **Кольцо контекста и стоимость сессии.** Кнопка в заголовке стала кольцом, заполняемым по расходу контекста, а панель показывает стоимость всей сессии рядом с процентом. Стоимость раньше суммировалась по загруженным сообщениям и занижалась для длинной сессии; теперь предпочитается накопленное сервером `session.cost`.
- **Чат больше не теряет сообщения по ходу.** «Загрузить старые» сбрасывал `hasMore` после загрузки, а каждое следующее обновление экрана (фокус, возврат из фона, реконнект) заменяло переписку страницей, обрезанной до настройки, — сообщения исчезали до перезахода. Теперь старые сообщения сохраняются, если полная история уже известна.
- **«Загрузить старые» действительно грузит всё.** Запрос шёл без `limit`, сервер отдавал свои 50 сообщений по умолчанию, и стор помечал историю загруженной — всё старше становилось недоступным. Теперь запрашивается максимальная страница (200) и обход идёт по курсору сообщений, пока он приносит новые строки.
- **Кнопка «стоп» есть всегда во время прогона.** Раньше она зависела от локального флага «я отправил», поэтому запуск, начатый не с этого экрана, прервать было нельзя — долгую сборку нечем было остановить.
- **Кнопки вложения и вставки не могут молча не сработать.** Необработанные промисы пикера и буфера обмена перехватываются и показываются пользователю; пикер закрывает клавиатуру и игнорирует повторный запуск, пока открыт.
- **Выбор уровня рассуждений при открытой клавиатуре.** Шторка оставалась за клавиатурой и последняя строка была недоступна; теперь клавиатура закрывается, а шторка поднимается вместе с ней, как у выбора модели.
- **Список сессий больше не обрезан.** V2-транспорт не читал курсор ответа (сервер по умолчанию отдаёт 50), V1 — заголовок `x-next-cursor` (100), поэтому сессии, видимые в TUI, отсутствовали в приложении. Теперь оба обходят курсор, с ограничением и дедупликацией.
- **Туннели работают.** Запросы несут `ngrok-skip-browser-warning` и `Bypass-Tunnel-Reminder`; без них ngrok отвечал своей страницей, а приложение сообщало о неверном пароле.
- **В уведомлениях нет серверного текста.** Уведомления о подтверждении и о вопросе — фиксированные строки: шторка читается с заблокированного телефона, а детали (имена инструментов, пути, команды) присылает сервер.
- **Репозиторий переименован** в `opencode-v1-v2-mobile`.

### 0.2.30

- **Неудачный прогон теперь объясняет причину.** Когда прогон падает — например, бесплатная модель отвечает `429 Free usage limit reached` — сервер записывает причину в assistant-сообщение и не присылает текст ответа. Чат рисовал пузырь без содержимого, поэтому сессия, которая на самом деле падала с ошибкой, выглядела зависшей и переставшей отвечать. Теперь причина показывается в пузыре красным, ровно там, где был бы ответ, и остаётся видимой после перезахода в сессию — она берётся из переписки.

### 0.2.29

- **Уточнение можно отправить, пока агент ещё работает.** Композер не отправлял сообщение до конца прогона, и добавить мысль по ходу можно было только дождавшись ответа. Теперь блокируется лишь отправка, которая уже в пути; сервер, как и раньше, ставит следующий запрос в очередь.
- **Отвеченные вопросы остаются в диалоге.** Карточка вопроса пропадала сразу после того, как сервер принимал ответ, и единственным напоминанием оставался двухсекундный отклик. Теперь она остаётся на месте вопроса — свёрнутая в одну строку, а по нажатию раскрывается со списком вариантов и отмеченными ответами.
- **«Сообщений на странице» теперь считает запросы, а не сообщения.** На один запрос агент обычно выдаёт десятки записей (шаг на каждый вызов инструмента), поэтому настройка выглядела нерабочей — 50 «сообщений» часто были одним обращением. Теперь страница измеряется вашими запросами и всегда начинается с одного из них. Сессии, открытые до этой версии, получают значение по умолчанию: старые числа несопоставимы.

### 0.2.28

- **Вернулась стоимость сообщения на серверах 2.2.5 и новее.** Сервер теперь передаёт присланную провайдером сумму как есть, а `opencode-go` присылает ноль, поэтому футеру нечего было показать и строка стоимости пропадала целиком. Если цена от сервера нулевая, приложение считает её по каталогу модели — input, output, размышления и кэш, той же формулой, что и сервер.
- **Чат больше не зависает после долгого сворачивания приложения.** Пока приложение было в фоне, поток событий копился; при возврате весь бэклог применялся разом, и каждое обновление заново перерисовывало и разбирало markdown всего сообщения — поток JS не успевал отдать управление, и тапы с навигацией не работали до конца прогона. Теперь обновления частей склеиваются, а поток уступает управление после каждого чанка.

### 0.2.27

- **Инструменты и мысли в чате идут в том же порядке, что и на компьютере.** Раньше ответ агента выглядел как «стена размышлений сверху, все вызовы инструментов внизу»: промежуточные реплики модели между шагами терялись в общей куче, а строка «Выполнено команд: N» повторялась на каждом шаге. Теперь каждый шаг показывает свои размышления, свою строку инструментов и свой текст в том порядке, в котором их выдала модель: запрос → мысли → инструменты → «Now the plan: …» → снова инструменты → окончательный ответ. Шапка «Assistant + модель» одна на весь прогон.
- **В конце — стоимость всего прогона, а не последнего шага.** Футер показывал токены и деньги только последнего roundtrip, из-за чего длинный прогон выглядел в разы дешевле, чем был. Теперь суммируются все шаги от вашего сообщения до конца ответа.
- **Метки команд снова совпадают с сервером.** `isCommandRun` и детали вызова знали только `bash`, а V2 называет инструмент `shell`: реальные запуски получали метку «Выполнено инструментов» с иконкой пазла и теряли командное превью. Исправлено.
- **Убрана привязка к Google Play.** Приложение не публикуется в магазинах, поэтому запрос оценки через Play In-App Review (`expo-store-review`) удалён вместе с зависимостью, счётчиком сессий в SecureStore и политикой порога. В APK больше нет кода магазина.

### 0.2.26

- **Возвращён правильный вид чата.** В 0.2.25 блок вопросов занял половину экрана, и сообщения уезжали вверх с пустой полосой над полем ввода: у `ScrollView` в React Native `flexGrow: 1` по умолчанию, поэтому даже пустой блок тянулся вверх. Теперь он не растёт, а сжимается только когда карточка не влезает. Закреплено тестом.

### 0.2.25

Дополнительно блок вопросов с вариантами ответа стал прокручиваемым: раньше при висящих вопросах он выталкивал строку ввода за пределы экрана, и написать в чат было нельзя, не закрыв клавиатуру. Теперь строка ввода видна всегда, а варианты ответа прокручиваются в оставшемся месте. Покрыто тестами.

### 0.2.24

Раньше сервер V2 игнорировал заголовок с папкой при создании сессии и складывал все новые сессии в свой рабочий каталог — обычно `~`. Теперь папка передаётся в теле запроса (`location.directory`); покрыто HTTP-тестом SDK.
- **Поле ввода больше не прячется за клавиатурой.** При наборе ответа клавиатура перекрывала строку ввода: приложение поднимало интерфейс всего на высоту системной панели навигации вместо высоты клавиатуры (ошибка в расчёте высоты, а не в самой клавиатуре). Теперь отступ берётся из системного отступа клавиатуры; исправление общее для всех экранов с вводом — чат, новая сессия, подключения. Покрыто тестом расчёта.

## Коротко о проекте (для тех, кто просматривает, и для ИИ-агентов)

- **Что это:** нативный Android-клиент (Expo / React Native, TypeScript) к [opencode](https://github.com/sst/opencode) — открытому AI-агенту для программирования.
- **Что это не:** не модель, не хостинг, не бэкенд. Своего сервера нет; промпты, код и креденшелы не покидают устройство никуда, кроме вашего же сервера.
- **Архитектура:** устройство общается напрямую с `opencode serve` по HTTPS с Basic-авторизацией. Два транспорта: V2 (`/api/*`, opencode 2.x) и V1 (`/session`, `/global/*`, opencode 1.x). Выбор определяется при подключении (`src/lib/api-detect.ts`) и может быть включён принудительно в настройках.
- **Как получить:** APK из [Releases](https://github.com/cfyz1297/opencode-v1-v2-mobile/releases/latest); ставится поверх предыдущих версий, подписан постоянным ключом.
- **Как запустить:** поднять `opencode serve` в доступном месте, ввести адрес в приложении. Локальная сеть, Tailscale, Cloudflare Tunnel и ngrok — работают все.
- **Требования:** Android 7+ (minSdk 24), сервер opencode 1.18+ или 2.x, сетевой доступ к нему.
- **Структура кода:** `app/` (экраны Expo Router), `src/lib` (SDK, транспорты, чистые хелперы — почти всё покрыто юнит-тестами), `src/stores` (zustand), `src/components` (UI). `HANDOFF.md` — рабочий инженерный журнал, `docs/` — разбор апстрима и отчёт по безопасности.
- **Проверки:** `npm test` (746 тестов, встроенный раннер node), `npm run typecheck`, `npm run check:versions`, `npm run test:coverage` (≈98 % строк).
- **Машиночитаемая сводка:** [`llms.txt`](llms.txt).
- **Лицензия:** MIT (унаследована от оригинала).
