# Проверка безопасности 0.3.17

Дата: 2026-11-14. Версия 0.3.17 (82), тестовый билд. Предыдущий отчёт: `docs/security-review-0.3.15.md`.

Проверялось: откат 0.3.16 (удаление канала после `startForeground`, ронявшее приложение) и единственная новая строка — `NotificationManager.cancel(NOTIFICATION_ID)` после `startForeground`, чтобы убрать карточку «Сессия выполняется». Метод: дифф против 0.3.15 (`git diff df61066`), `npx expo prebuild` (проверка, что исходник попадает в `android/`), `npm audit`, статический скан секретов, прогон `check:versions`, `typecheck`, `test`.

## Что изменилось и его границы безопасности

| Изменение | Границы безопасности |
|---|---|
| Откат 0.3.16 | Код `KeepAliveService.kt`, `NotifyModule.kt` и тест возвращены к состоянию 0.3.15, в котором приложение работало. Убраны: удаление канала после `startForeground` (причина краша), ветка `manager.cancel` для pre-Oreo, `setSound(null, null)`. |
| `cancel(NOTIFICATION_ID)` после `startForeground` | Отменяет только собственное уведомление сервиса. В нём были две фиксированные строки i18n — никаких данных пользователя, путей или URL. Разрешений не добавляет. Канал не удаляется, поэтому система не теряет привязку foreground-сервиса к уведомлению (именно это ломало приложение в 0.3.16). |

## Проверено, изменений не потребовалось

- **Новых разрешений и нативного кода нет.** Правка — одна строка в существующем сервисе.
- **Канал, иконки, публикация уведомлений** (`NotifyModule.kt`) не менялись относительно 0.3.15: `PendingIntent` иммутабельный с явным компонентом, id сессии проверяется в JS, иконки — статические векторы только с `#FFFFFFFF`.
- **Тексты уведомлений** не менялись: permissions/questions — фиксированные ключи, completed/errors — `sanitizeBody`.
- **Сервис не экспортирован** (`android:exported="false"`), `HeadlessJsTaskService` не отдаёт Binder наружу.
- **Секреты:** статический скан отслеживаемых файлов чист (единственное совпадение — фиктивный `AIzaSyDummyGoogleKeyValue…` в `custom-provider.test.ts`); gitleaks в CI.

## `npm audit`

**3 записи, все moderate** — `minimatch` 10.2.6 в `expo → @expo/fingerprint` (GHSA-g3hv-75wg-m249). Сборочная цепочка, в рантайме APK не используется. Осознанно принятый остаток, как в 0.3.0–0.3.15.

## Известные остатки (приняты)

- **Android может игнорировать отмену уведомления foreground-сервиса на части версий/OEM-прошивок** — тогда карточка останется, но краша не будет: канал и сервис не трогаются. Это осознанный компромисс после падения 0.3.16.
- **Проверить доставку уведомления вручную** можно только реальным прогоном: кнопки тестового уведомления нет с 0.3.15.
- **Уведомление о завершении приходит для любой сессии на этом сервере**, включая запущенную из терминала.
- **`FOREGROUND_SERVICE_DATA_SYNC` ограничен 6 часами в сутки на Android 15+.**
- **Пароль по `http://`, `usesCleartextTraffic=true`, отсутствие pinning** — без изменений.

## Не проверялось

Фактическое поведение на устройстве (локального Android SDK нет): проверка — установка APK, запуск прогона, взгляд в шторку. Компиляция Kotlin выполняется CI.
