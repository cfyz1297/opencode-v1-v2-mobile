# Проверка безопасности 0.3.15

Дата: 2026-11-13. Версия 0.3.15 (80), тестовый билд. Предыдущий отчёт: `docs/security-review-0.3.14.md`.

Проверялось: удаление тестового уведомления и блока логов уведомлений из настроек, удаление `sendTest()` из `src/lib/notifications.ts` и его ключей из трёх локалей, сокращение внутреннего логирования уведомлений. Метод: чтение диффа, поиск неиспользуемых ключей переводов и экспортов, `npm audit`, статический скан секретов, прогон `check:versions`, `typecheck`, `test`, `test:coverage`.

## Что изменилось и его границы безопасности

| Изменение | Границы безопасности |
|---|---|
| Удалён блок диагностики в настройках | Убрал единственное место, где последние решения по уведомлениям (категория + исход) показывались пользователю в UI. Новых данных это не открывало, удаление только уменьшает поверхность. Отчёт диагностики соединения (`src/lib/diagnostics.ts`) не тронут и по-прежнему включает строки лог-буфера. |
| Удалён `sendTest()` | Функция публиковала уведомление с фиксированными строками мимо проверки `AppState` (это было нужно для ручной проверки). Удаление убирает единственный путь отправки, который обходил политику «только в фоне». Публикация реальных уведомлений не изменилась. |
| Логирование ограничено отказами | Пишутся только `disabled`, `no-permission`, `held`, `deduped`, `failed`. Строка `posted` и тик фонового опроса больше не пишутся: тик раз в 5 секунд вымывал кольцевой буфер на 200 записей и обнулял ценность отчёта диагностики соединения. Содержимое строк — категория и исход, без заголовков сессий, путей и URL. |
| Удалены ключи `settings.notifications.test.*` и `settings.notifications.diagnostics.*` | В трёх локалях; проверено, что ни один ключ раздела `settings.notifications` больше не остался неиспользованным. |

## Проверено, изменений не потребовалось

- **Новых разрешений и нативного кода нет.** Правки этого релиза — удаление кода и UI.
- **Статус разрешения в настройках остался** — единственная строка раздела; предупреждение о блокировке и `Linking.openSettings()` работают как раньше (есть тест).
- **Политика показа не изменилась:** `send()` молчит при `AppState === "active"`, отложенные (3 с) сбрасываются в фон и при возврате; фоновый опрос помечает свои уведомления `force`.
- **Тексты уведомлений** не менялись: permissions/questions — фиксированные ключи, completed/errors — `sanitizeBody`.
- **Секреты:** статический скан отслеживаемых файлов чист (единственное совпадение — фиктивный `AIzaSyDummyGoogleKeyValue…` в `custom-provider.test.ts`); gitleaks в CI.

## `npm audit`

**3 записи, все moderate** — `minimatch` 10.2.6 в `expo → @expo/fingerprint` (GHSA-g3hv-75wg-m249). Сборочная цепочка, в рантайме APK не используется. Осознанно принятый остаток, как в 0.3.0–0.3.14.

## Известные остатки (приняты)

- **Проверить доставку уведомления вручную теперь можно только запуском прогона**: кнопки тестового уведомления нет. Статус системного разрешения по-прежнему виден в настройках.
- **Причина отсутствующего уведомления больше не видна в UI** — только в отчёте диагностики соединения (там строки `notifications`/`keepalive` сохраняются). Это осознанно: раздел настроек должен оставаться простым.
- **Уведомление о завершении приходит для любой сессии на этом сервере**, включая запущенную из терминала.
- **`IMPORTANCE_NONE` для keep-alive** — документированный способ не показывать уведомление сервиса; отдельные прошивки могут печатать системную строку «приложение работает в фоне».
- **Пароль по `http://`, `usesCleartextTraffic=true`, отсутствие pinning** — без изменений.

## Не проверялось

Фактический вид раздела настроек на устройстве (локального Android SDK нет) — проверяется установкой APK.
