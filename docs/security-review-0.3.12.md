# Проверка безопасности 0.3.12

Дата: 2026-11-13. Версия 0.3.12 (77), тестовый билд. Предыдущие отчёты: `docs/security-review-0.3.11.md`, `docs/security-review-0.3.10.md`, `docs/security-review-0.3.9.md`.

Проверялось: изменения 0.3.12 — фоновый опрос по серверному `/api/session/active`, безусловное логирование тика, сокращение окна отложенных уведомлений до 3 с и их сброс при возврате в приложение, дедупликация завершений по ключу `end-<session>`, защита `refreshPending` от параллельных вызовов, выбор клиента соединения по каталогу сессии. Метод: чтение диффа, `npm audit`, статический скан секретов, прогон `check:versions`, `typecheck`, `test`, `test:coverage`.

## Что изменилось и его границы безопасности

| Изменение | Границы безопасности |
|---|---|
| Опрос `/api/session/active` в фоне | Тот же клиент соединения и та же авторизация, что у остальных запросов; новых эндпоинтов, полномочий и хранилищ нет. Список возвращает только идентификаторы сессий. Запрос выполняется только при `AppState !== "active"`. |
| `notifyRunEnded` читает транскрипт | Для сессии, исчезнувшей из списка активных, вызывается `session.messages` — тот же запрос, что экран чата делает при открытии. Тело уведомления: заголовок сессии или `message.error.message` через `sanitizeBody` (правило 0.3.2 сохранено). |
| Клиент по каталогу сессии (`clientFor`) | Выбирает соединение из уже загруженного списка сессий пользователя; каталог — собственное поле сессии, не пользовательский ввод из сети. При отсутствии совпадения — основной клиент. |
| Окно отложенных уведомлений 3 с + `dropHeld` при возврате | Буфер только в памяти, максимум 5 записей, не сериализуется и не уходит в сеть. Сокращение окна и сброс уменьшают время, в течение которого содержимое уведомления (заголовок сессии) держится в памяти. |
| Дедупликация `end-<session>` | Ключ — идентификатор сессии, не текст. Кулдаун 20 с. Ничего не логируется и не раскрывается. |
| `refreshPending` без параллельных вызовов | Устраняет только дубли уведомлений; данные и права те же. |
| Лог `[watch] tick (state)` | Пишется только состояние приложения (`active`/`background`); идентификаторы сессий — лишь при `run ended`, и они уже видны в окне диагностики. Не содержит заголовков, путей, URL и учётных данных. |

## Проверено, изменений не потребовалось

- **Новых разрешений и нативного кода нет.** `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC`, `POST_NOTIFICATIONS` — из 0.3.8/0.3.9; `blockedPermissions` — только `SYSTEM_ALERT_WINDOW` (есть тест).
- **Уведомления о вопросах и разрешениях** по-прежнему несут фиксированные ключи i18n без интерполяции; серверный текст вопроса и команды на экран блокировки не попадает.
- **`send()`** не публикует ничего при `AppState === "active"`; `force` используется только в коде, который по построению выполняется в фоне (опрос и отложенная доставка при переходе в фон).
- **Права доступа к настройкам и паролям** не менялись; опрос использует тот же `client`, что и UI.
- **Секреты:** статический скан отслеживаемых файлов чист (единственное совпадение — фиктивный `AIzaSyDummyGoogleKeyValue…` в `custom-provider.test.ts`); gitleaks в CI зелёный.

## `npm audit`

**3 записи, все moderate** — `minimatch` 10.2.6 в `expo → @expo/fingerprint` (GHSA-g3hv-75wg-m249). Сборочная цепочка, в рантайме APK не используется. Осознанно принятый остаток, как в 0.3.0–0.3.11.

## Известные остатки (приняты)

- **Уведомление о завершении приходит для любой сессии, которая выполнялась на этом сервере**, включая запущенную из терминала или другого клиента: серверный список — единственный источник правды, а клиент не может надёжно отличить «мою» сессию. Заголовок в уведомлении — название сессии.
- **Опрос раз в 5 с при активном прогоне** — 1 + N запросов за тик к собственному серверу; при отсутствии прогонов сеть не трогается (список пуст, `refreshPending` не вызывается).
- **Doze/App Standby** могут приостановить сеть на длительное время — при заблокированном экране в глубоком сне уведомление задержится до пробуждения; foreground-сервис смягчает, но не отменяет это.
- **Прогон, начатый не на этом сервере**, не отслеживается.
- **`FOREGROUND_SERVICE_DATA_SYNC` ограничен 6 часами в сутки на Android 15+.**
- **Пароль по `http://`, `usesCleartextTraffic=true`, отсутствие pinning** — без изменений.

## Не проверялось

Фактическая доставка на заблокированный телефон (локального Android SDK нет): проверка — установка APK, запуск прогона, сворачивание, затем блок диагностики в настройках (ожидаемые строки: `[watch] tick (background)`, `posted`, `[keepalive] started`). Поведение под Doze. iOS: поллинг тот же, foreground-сервиса нет.
