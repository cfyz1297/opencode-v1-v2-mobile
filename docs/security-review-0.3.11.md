# Проверка безопасности 0.3.11

Дата: 2026-11-13. Версия 0.3.11 (76), тестовый билд. Предыдущие отчёты: `docs/security-review-0.3.10.md`, `docs/security-review-0.3.9.md`, `docs/security-review-0.3.8.md`.

Проверялось: изменения 0.3.11 — отложенные (held) уведомления для гонки «отправил и свернул», `force` для уведомлений из фонового опроса, блок диагностики уведомлений в настройках, защита keep-alive от пустых строк перевода, логирование решений и тиков. Метод: чтение диффа, `npm audit`, статический скан секретов, прогон `check:versions`, `typecheck`, `test`, `test:coverage`.

## Что изменилось и его границы безопасности

| Изменение | Границы безопасности |
|---|---|
| Отложенные уведомления (`held`, 10 с) | Хранятся только в памяти процесса, максимум 5 записей, ничего не пишется на диск и в сеть. Сбрасываются при уходе приложения в фон и через 10 секунд отбрасываются. Содержимое — те же поля, что и раньше (`title`/`body` после `sanitizeBody`, `sessionId`, `category`). |
| `force` для фонового опроса | Не меняет содержимое уведомления, а снимает повторную проверку `AppState` для события, которое заведомо сгенерировано в фоне. Тексты остаются фиксированными ключами i18n для permissions/questions, `sanitizeBody` — для completed/errors. |
| Блок диагностики в настройках | Показывает последние 8 строк лог-буфера с тегами `notifications`, `keepalive`, `watch`. Строки содержат категорию, исход (`posted`/`held`/`no-permission`/`disabled`/`error`) и текст ошибки нативной отправки. **Не содержат**: названий сессий, текста сообщений, путей, URL, учётных данных, id запросов. `title`/`body` уведомлений в лог не пишутся. Текст `selectable` — пользователь может скопировать его сам; автоматической отправки нет. |
| Keep-alive fallback | При недоступном переводе сервис получает литеральные английские строки вместо `undefined`. Раньше такая ошибка могла не дать сервису стартовать, а это тихая потеря всех фоновых уведомлений. Новых данных в уведомлении нет. |
| Логирование keep-alive | Пишет только `started`/`stopped` и текст исключения нативного вызова; id сессий, заголовки и URL туда не попадают. |

## Проверено, изменений не потребовалось

- **Новых разрешений и нативных компонентов нет.** `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC`, `POST_NOTIFICATIONS` — из 0.3.8/0.3.9; `blockedPermissions` по-прежнему только `SYSTEM_ALERT_WINDOW` (есть тест).
- **Канал и триггер** не менялись (`prompts`, HIGH, `{channelId}`); тестовое уведомление идёт тем же путём.
- **Фоновый опрос** по-прежнему работает только при `AppState !== "active"` и только для сессий, уже известных клиенту; эндпоинты и клиент те же. `force` не расширяет набор запросов.
- **Дедупликация** не ослаблена: held-запись проходит те же проверки при сбросе, повторный `flushHeld()` не публикует дважды (есть тест).
- **Утечка секретов через held-буфер невозможна**: буфер не сериализуется и живёт до перезапуска процесса.
- **Секреты:** статический скан отслеживаемых файлов чист (единственное совпадение — фиктивный `AIzaSyDummyGoogleKeyValue…` в `custom-provider.test.ts`); gitleaks в CI зелёный.

## `npm audit`

**3 записи, все moderate** — `minimatch` 10.2.6 в `expo → @expo/fingerprint` (GHSA-g3hv-75wg-m249). Сборочная цепочка, в рантайме APK не используется. Осознанно принятый остаток, как в 0.3.0–0.3.10.

## Известные остатки (приняты)

- **Диагностика показывает только последние 8 строк** — этого хватает, чтобы отличить «held», «нет разрешения» и «не возникало», но не для долгой истории.
- **Уведомления приходят только в фоне.** Если пользователь в приложении, алерт откладывается и либо публикуется при уходе в фон (в пределах 10 с), либо отбрасывается.
- **Прогон, начатый не с этого устройства**, не отслеживается — клиент о нём не знает.
- **`FOREGROUND_SERVICE_DATA_SYNC` ограничен 6 часами в сутки на Android 15+.**
- **Пароль по `http://`, `usesCleartextTraffic=true`, отсутствие pinning** — без изменений.

## Не проверялось

Фактическая доставка на заблокированный телефон (локального Android SDK нет): проверка — установка APK, запуск сессии, сворачивание, затем чтение блока диагностики в настройках. Поведение `dataSync`-сервиса при исчерпании суточной квоты на Android 15. iOS: опроса и сервиса нет, поведение прежнее.
