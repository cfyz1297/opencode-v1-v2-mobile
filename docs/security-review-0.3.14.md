# Проверка безопасности 0.3.14

Дата: 2026-11-13. Версия 0.3.14 (79), тестовый билд. Предыдущие отчёты: `docs/security-review-0.3.13.md`, `docs/security-review-0.3.12.md`, `docs/security-review-0.3.11.md`.

Проверялось: изменения 0.3.14 — нативный модуль `Notify` вместо expo-notifications на Android, монохромные векторные иконки по категориям (`plugins/native/res/drawable`), deep-link из уведомления (`opencode://session/<id>`), сокрытие постоянного уведомления keep-alive через канал `IMPORTANCE_NONE`, meta-data `expo.modules.notifications.default_notification_icon`. Метод: чтение диффа и кода React Native/expo-router, `npx expo prebuild` дважды подряд (идемпотентность и фактический манифест), `npm audit`, статический скан секретов, прогон `check:versions`, `typecheck`, `test`, `test:coverage`.

## Что изменилось и его границы безопасности

| Изменение | Границы безопасности |
|---|---|
| `NotifyModule.kt` публикует уведомления сам | Тот же `NotificationManager`, тот же канал `prompts`, те же title/body, которые раньше передавались в expo-notifications (фиксированные ключи i18n или `sanitizeBody`). Ничего нового не читается: параметры идут из JS, где `send()` уже отфильтровал категорию и разрешение. |
| `notify(...)` возвращает Promise | Метод не бросает исключения в JS как unhandled: ошибка реджектится с текстом, `deliver()` её ловит и пишет в лог-буфер (окно диагностики). |
| Иконки `plugins/native/res/drawable/notif_*.xml` | Статические векторные ресурсы, только `#FFFFFFFF` и прозрачный фон. Никаких bitmap, внешних файлов и динамической подстановки. Тест запрещает им рисовать фон. |
| Deep link `opencode://session/<id>` в `PendingIntent` | `Intent.ACTION_VIEW` с явным `component` из launcher-intent (не из пользовательских данных). Сам id проверяется в JS `isSafeSessionId` перед рендером; `PendingIntent` — `FLAG_IMMUTABLE`, поэтому другая программа не может подменить содержимое. Внешняя сеть не задействована. |
| Канал `keepalive` = `IMPORTANCE_NONE` | Уведомление foreground-сервиса не показывается, но сервис сохраняет статус. Идентификатор канала фиксированный; при обнаружении старого канала с другой важностью он удаляется и создаётся заново (иначе важность не изменить). Данных в уведомлении нет — только i18n-строки. |
| Meta-data `default_notification_icon` | Указывает на наш `@drawable/notif_default`. Плагин должен стоять в `app.json` до `expo-notifications`: моды применяются в обратном порядке, иначе expo перезапишет значение на полноцветный PNG (это и давало белый квадрат). Закреплено тестом и проверено двумя `expo prebuild`. |
| `NotifyPackage` в `MainApplication` | Регистрация пакета идёт тем же способом, что `KeepAlivePackage`; `createViewManagers` пуст. |

## Проверено, изменений не потребовалось

- **Новых разрешений нет:** `POST_NOTIFICATIONS`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC` — из 0.3.8/0.3.9; `blockedPermissions` — только `SYSTEM_ALERT_WINDOW` (есть тест).
- **Сервис не экспортирован** (`android:exported="false"`), `NotifyModule` вообще не сервис — только внутренний JS-мост.
- **Тексты уведомлений** не изменились: permissions/questions — фиксированные ключи без интерполяции, completed/errors — `sanitizeBody` (правило 0.3.2).
- **iOS-путь** остаётся на expo-notifications; ветка выбирается по `Platform.OS` и наличию нативного модуля.
- **Секреты:** статический скан отслеживаемых файлов чист (единственное совпадение — фиктивный `AIzaSyDummyGoogleKeyValue…` в `custom-provider.test.ts`); gitleaks в CI.

## `npm audit`

**3 записи, все moderate** — `minimatch` 10.2.6 в `expo → @expo/fingerprint` (GHSA-g3hv-75wg-m249). Сборочная цепочка, в рантайме APK не используется. Осознанно принятый остаток, как в 0.3.0–0.3.13.

## Известные остатки (приняты)

- **`IMPORTANCE_NONE` для keep-alive** — документированный способ не показывать уведомление сервиса; отдельные прошивки (Xiaomi/Huawei) могут всё равно печатать системную строку «приложение работает в фоне». Это поведение ОС, не приложения.
- **Один id на сессию и категорию**: повторное уведомление того же рода заменяет предыдущее вместо стека. Осознанно, чтобы «Задача завершена» не копилась.
- **Deep link без `directory`**: если у пользователя несколько серверов и сессия принадлежит не текущему, экран откроется для текущего соединения. Ровно то же поведение было у прежнего маршрута через `router.push` в `_layout.tsx`.
- **Уведомление о завершении приходит для любой сессии на этом сервере**, включая запущенную из терминала.
- **`FOREGROUND_SERVICE_DATA_SYNC` ограничен 6 часами в сутки на Android 15+.**
- **Пароль по `http://`, `usesCleartextTraffic=true`, отсутствие pinning** — без изменений.

## Не проверялось

Компиляция Kotlin и фактический вид иконок в статус-баре (локального Android SDK нет — проверяет CI и установка APK). Поведение `IMPORTANCE_NONE` на прошивках с собственной политикой уведомлений. iOS.
