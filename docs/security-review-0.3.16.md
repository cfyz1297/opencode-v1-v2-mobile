# Проверка безопасности 0.3.16

Дата: 2026-11-14. Версия 0.3.16 (81), тестовый билд. Предыдущий отчёт: `docs/security-review-0.3.15.md`.

Проверялось: изменение способа скрыть уведомление foreground-сервиса — канал `keepalive` теперь удаляется сразу после `startForeground` (вместо `IMPORTANCE_NONE`, который Android принудительно повышает до `LOW`), удалён неиспользуемый `hideKeepAliveChannel` из `NotifyModule.kt`. Метод: чтение кода Android (`NotificationChannel`/FGS-поведение), `npx expo prebuild` (проверка, что исходник попадает в `android/`), `npm audit`, статический скан секретов, прогон `check:versions`, `typecheck`, `test`, `test:coverage`.

## Что изменилось и его границы безопасности

| Изменение | Границы безопасности |
|---|---|
| Удаление канала сразу после `startForeground` | Новых разрешений и данных нет. Удаление канала убирает только уведомление сервиса: в нём не было пользовательских данных (две фиксированные строки i18n). Сервис остаётся в foreground-состоянии — то есть процесс и headless-задача продолжают работать, как и задумано. Канал пересоздаётся при следующем старте, поэтому никакого состояния на диск не пишется. |
| Канал создаётся с `IMPORTANCE_NONE` и `setSound(null, null)` | Значение больше не влияет на видимость (канал удаляется), но гарантирует, что если удаление не удастся на какой-то прошивке, уведомление хотя бы не звучит и не вибрирует. |
| Старый канал удаляется до `startForeground` | Важность канала неизменяема: без пересоздания `startForeground` упал бы на канале с прежней важностью, а сервис не получил бы foreground-статус — то есть пропали бы фоновые уведомления. Обработка ошибок не ослаблена. |
| Удалён `hideKeepAliveChannel` | Функция больше не вызывается (её заменил `showHiddenOngoing` внутри сервиса). Удаление уменьшает поверхность: меньше кода с доступом к `NotificationManager`. |

## Проверено, изменений не потребовалось

- **Новых разрешений нет:** `POST_NOTIFICATIONS`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC` — из 0.3.8/0.3.9; `blockedPermissions` — только `SYSTEM_ALERT_WINDOW` (есть тест).
- **Сервис не экспортирован** (`android:exported="false"`), `onBind` отсутствует (`HeadlessJsTaskService` не даёт Binder наружу), входных точек из других приложений нет.
- **Тексты уведомлений** не менялись: permissions/questions — фиксированные ключи, completed/errors — `sanitizeBody`; keep-alive-строки теперь вообще не видны, так как уведомление удаляется.
- **Отправка уведомлений** (нативный `NotifyModule`) не менялась с 0.3.14: `PendingIntent` иммутабельный и с явным компонентом, id сессии проверяется в JS.
- **Секреты:** статический скан отслеживаемых файлов чист (единственное совпадение — фиктивный `AIzaSyDummyGoogleKeyValue…` в `custom-provider.test.ts`); gitleaks в CI.

## `npm audit`

**3 записи, все moderate** — `minimatch` 10.2.6 в `expo → @expo/fingerprint` (GHSA-g3hv-75wg-m249). Сборочная цепочка, в рантайме APK не используется. Осознанно принятый остаток, как в 0.3.0–0.3.15.

## Известные остатки (приняты)

- **Удаление канала после `startForeground` — недокументированный приём.** Поддерживаемого способа скрыть уведомление FGS нет: Android требует его показывать. Приём опирается на то, что удаление канала отменяет уведомление, но не снимает foreground-состояние; на Android 13+ пользователь и так может смахнуть уведомление FGS, не останавливая сервис. На отдельных прошивках (Xiaomi/Huawei) поведение может отличаться.
- **Системный индикатор.** На Android 12+ ОС может показывать собственный значок «приложение работает в фоне» — это индикатор самой системы, приложением не управляется.
- **Проверить доставку уведомления вручную** можно только реальным прогоном: кнопки тестового уведомления нет с 0.3.15.
- **Уведомление о завершении приходит для любой сессии на этом сервере**, включая запущенную из терминала.
- **`FOREGROUND_SERVICE_DATA_SYNC` ограничен 6 часами в сутки на Android 15+.**
- **Пароль по `http://`, `usesCleartextTraffic=true`, отсутствие pinning** — без изменений.

## Не проверялось

Поведение удаления канала на реальном устройстве и на OEM-прошивках (локального Android SDK нет): проверка — установка APK, запуск прогона, сворачивание, взгляд в шторку. Компиляция Kotlin выполняется CI.
