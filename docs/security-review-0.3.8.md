# Проверка безопасности 0.3.8

Дата: 2026-11-12. Версия 0.3.8 (73), тестовый билд. Предыдущие отчёты: `docs/security-review-0.3.2.md`, `docs/security-review-server-api.md`, `docs/security-review-0.2.21.md`.

Проверялось: исправления 0.3.8 — карточка отвеченного вопроса внутри транскрипта, политика показа уведомлений на переднем плане, foreground-сервис `KeepAliveService` (новый нативный код + разрешения + prebuild-плагин), канал уведомлений перед отправкой. Метод: чтение диффа и кода, `npm audit`, статический скан секретов по отслеживаемым файлам, инварианты в тестах, разбор манифеста после `expo prebuild`, прогон `check:versions`, `typecheck`, `test`, `test:coverage`.

## Foreground-сервис: поверхность атаки

- **Новые разрешения:** `android.permission.FOREGROUND_SERVICE` и `FOREGROUND_SERVICE_DATA_SYNC`. Оба нужны для запуска сервиса с типом `dataSync` на Android 14+; доступа к данным, сети или другим приложениям они не дают. `POST_NOTIFICATIONS` не блокируется (`blockedPermissions` содержит только `SYSTEM_ALERT_WINDOW`, проверено тестом).
- **Сервис не экспортирован** (`android:exported="false"`), `onBind` возвращает `null` — у него нет Binder-интерфейса и нет входных точек из других приложений. Запуск и остановка идут только из JS-моста `KeepAlive` внутри процесса приложения.
- **Текст постоянного уведомления** — фиксированные ключи i18n (`notifications.keepAlive.*`), без данных сессии, пути или серверного текста. На экране блокировки видно только «Сессия выполняется».
- **Никакого нового сетевого трафика.** Сервис не открывает соединений: он только держит процесс в foreground-важности, пока живёт уже существующий SSE-поток к серверу пользователя.
- **`START_NOT_STICKY`:** убитый процесс не resurrect'ит сервис (и его уведомление) для прогона, о котором приложение уже не знает.
- **Kotlin-код** не использует reflection, `DexClassLoader`, внешние файлы и не читает пользовательские данные; все три файла — только работа с `NotificationManager`/`startForeground`.
- **`notification_icon`** — ресурс, который создаёт сам `expo-notifications` из `assets/icon.png` на prebuild; произвольный контент туда не попадает.

## Проверено, изменений не потребовалось

- **Тексты уведомлений.** Permission/question по-прежнему несут фиксированные ключи переводов без интерполяции; completed/error — заголовок сессии и текст ошибки, прошедшие `sanitizeBody` (решение 0.3.2 сохранено). Новый показ на переднем плане не добавляет данных: те же поля, что и в фоне.
- **`setViewedSession`** принимает id сессии и только сравнивает его с id из события уведомления. Никаких запросов по этому id не строится; граница deep link (`isSafeSessionId`) не менялась.
- **`metadata.tool.messageID`** из V2-формы используется только как ключ для выбора места рендера карточки в уже загруженном списке сообщений. В URL, файловые пути и SQL он не попадает.
- **Манифест после prebuild.** `npx expo prebuild --platform android --no-install` выполнен локально: добавлены только `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC` и `<service android:exported="false">`; `SYSTEM_ALERT_WINDOW` остаётся `tools:node="remove"`, `usesCleartextTraffic="true"` и подпись на месте, `RECORD_AUDIO` не тронут.
- **Секреты.** Статический скан отслеживаемых файлов (private key, GitHub/AWS/Google/OpenAI/Slack/Stripe-токены) чист; единственное совпадение — фиктивный `AIzaSyDummyGoogleKeyValue…` в `custom-provider.test.ts`. Новые файлы секретов не добавляют.
- **Пароли серверов и SecureStore, backup-правила, телеметрия, deep links, markdown** — без изменений с 0.3.2, повторно не проверялись.
- **Fail-closed.** Мост `setKeepAlive` глушит любые исключения (нет нативного модуля, запрет старта сервиса из фона на Android 12+) и не влияет на поток событий; уведомление просто не показывается, если разрешение не выдано (`granted()`).

## `npm audit`

`npm audit` на 2026-11-12: **3 записи, все moderate** — `minimatch` 10.2.6 в `expo → @expo/fingerprint` (GHSA-g3hv-75wg-m249, DoS через globparts). Зависимость сборочной цепочки, в рантайме APK не используется; `npm audit fix --force` откатывает Expo и ломает проект. Осознанно принятый остаток, как в 0.3.0–0.3.2.

## Известные остатки (приняты)

- **Постоянное уведомление во время прогона** — цена foreground-сервиса; без него Android не даёт уведомлениям работать на заблокированном экране. Показывается только при активной сессии.
- **`FOREGROUND_SERVICE_DATA_SYNC` ограничен 6 часами в сутки на Android 15+.** Для агентских прогонов этого достаточно; при упоре в лимит система сама остановит сервис, уведомления продолжат работать, пока процесс жив.
- **Уведомления о completed/error несут заголовок сессии** — сохранённое решение 0.3.2: без него уведомление бесполезно, а данные ограничены перепиской самого пользователя.
- **Пароль по `http://`, `usesCleartextTraffic=true`, отсутствие pinning** — без изменений (самодельные серверы в Termux/LAN).

## Не проверялось

Компиляция Kotlin и установка APK на устройство (локального Android SDK нет — это делает CI), фактическая доставка уведомления на заблокированный телефон, поведение сервиса на Android 15 при исчерпании квоты `dataSync`, iOS (foreground-сервиса там нет, JS-мост отсутствует и молча деградирует).
